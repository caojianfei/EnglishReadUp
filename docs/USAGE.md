# 英语阅读提升 · 使用手册

把一篇外刊文章变成可检索、可复习的学习材料：抓正文和图片到本地 → 划词查音标、
听发音、选段让 AI 拆解 → 自动记生词和语法点 → 按间隔复习。

配套文档：`docs/DESIGN.md`（设计说明书，讲「为什么这么做」）。
本文只讲「怎么装、怎么开、怎么用」。

## 1. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows / macOS / Linux | 开发实测环境为 Windows 11 |
| Python | 3.11+（实测 3.13） | 后端。用 uv 建环境时不必预装，`uv venv` 自己带一个 |
| uv | 0.11+（实测 0.11.32），**可选** | 装依赖与启动后端（§2.1、§4.1） |
| Node.js | 20+（实测 22） | 前端构建 |
| 磁盘 | 约 1.5 GB | 本地词典库 811 MB + Playwright Chromium 约 150 MB + 文章与图片 |
| 网络 | 能访问 `api.deepseek.com` 与 `dict.youdao.com` | 选段解析用模型、发音用有道 |

**为什么需要无头浏览器**：Sixth Tone 是纯前端渲染站点，静态 HTML 里没有正文
（见 `DESIGN.md §5.1`）。所以首次安装必须下载 Chromium，抓这类站点时会自动启用。

**没有外网时**：项目能启动、能读已抓好的文章、能划词查释义（词典是本地文件）、
**能听已经点过喇叭的那些词**、能复习；但抓新文章、选段【解析】、以及第一次点某个
词的发音喇叭会失败。

## 2. 安装（只做一次）

### 2.1 后端

**推荐用 [uv](https://docs.astral.sh/uv/)** —— 建环境和装依赖快得多，而且之后不用手动 activate：

```bash
cd backend

uv venv --python 3.13                            # 建 backend/.venv
uv pip install -r requirements.txt               # 装依赖
uv run python -m playwright install chromium     # 装无头浏览器（约 150 MB，只下一次）
```

> `uv venv` 会自己找（必要时下载）3.13 解释器，不依赖系统 Python。
> `uv run` 会自动发现并使用 `backend/.venv`，**不需要 `activate`，也不需要 `pyproject.toml`**。

**没有 uv 时**用原生 venv：

```bash
cd backend

python -m venv .venv
.venv\Scripts\activate          # Windows (PowerShell / cmd)
source .venv/bin/activate       # macOS / Linux / Git Bash
pip install -r requirements.txt
python -m playwright install chromium
```

### 2.2 前端

```bash
cd frontend
npm install
```

> 用 **npm**，不要用 pnpm。pnpm 11 在本机会把 `@types/react`、`@types/react-dom`
> 装成空目录（`.ignored_*`），`tsc` 随即报 TS2688（`DESIGN.md §11`）。

### 2.3 词典库（划词要用，服务会自动装）

**划词的音标与释义全部来自本地词典库**（红线 3）。这三个文件约 816 MB，不进版本库，
所以**服务启动时会自检并自动补齐**：缺哪个下哪个，已有的不重下。

| 文件 | 来源 | 体积 | 用途 |
|---|---|---|---|
| `stardict.db` | [ECDICT](https://github.com/skywind3000/ECDICT)（MIT） | 约 **811 MB** | 中文释义、词性、考纲标签、词频 |
| `ipa_en_us.txt` | ipa-dict `en_US`（源自 cmudict，MIT） | 约 3.1 MB | 美音音标 |
| `ipa_en_uk.txt` | ipa-dict `en_UK`（源自 ipacards，GPL 3.0） | 约 1.6 MB | 英音音标 |

下载**在后台线程里跑，不堵启动** —— 文章、检索、生词本立刻可用，不必等 200 MB。
启动日志会写一行「词典数据缺失：… 已在后台开始下载」；进度看健康检查：

```bash
curl http://127.0.0.1:8010/api/health     # 看 dict.bootstrap
```

数据还没下完时划词，词卡会直接显示「正在下载 ECDICT 词库 42%」而不是让你去跑脚本。
下完自动生效，**不用重启**（划一次词就查得到）。

不想让它自动下载（离线、想自己控制时机）就设 `DICT_AUTODOWNLOAD=false` ——
这时划词会提示去跑脚本。手工入口仍在（缺什么装什么、已有的跳过）：

```bash
cd backend
python scripts/fetch_dicts.py            # 装/补
python scripts/fetch_dicts.py --verify   # 只体检，不联网
```

`--verify` 会打印索引构成、样例词条、考纲标签分布，以及 ipa-dict 对常见词的命中率 ——
怀疑数据坏了时看这个。
**没装也不是起不来**：划词会明确提示，其余功能照常。

> 这三个文件都在 `backend/data/` 下，**不进版本库**（`.gitignore` 已排除）。
> 想换台机器：整个 `data/` 拷过去即可，不用重下；忘了拷也没关系，启动会自己补。

### 2.4 验证安装

```bash
cd backend
python scripts/dev_check.py
```

应打印 `data_dir`、`db` 路径，以及建好的表清单。这一步会顺手初始化数据库，
所以**首次启动前先跑一次这个脚本，或直接启动服务也行**（服务启动时也会建表）。

## 3. 配置 `.env`

```bash
cd backend
cp .env.example .env      # Windows: copy .env.example .env
```

打开 `backend/.env`，至少填一项：

```ini
LLM_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
```

**去哪拿 key**：登录 <https://platform.deepseek.com> → API Keys → 新建。

### 全部配置项

| 变量 | 默认值 | 说明 |
|---|---|---|
| `DATA_DIR` | `./data` | 数据目录。相对路径按 `backend/` 解析，也可写绝对路径 |
| `FETCH_RATE_LIMIT` | `2.0` | 同一域名两次请求的最小间隔（秒），防被封 |
| `FETCH_TIMEOUT` | `25` | 单次 HTTP 请求超时（秒） |
| `RENDER_DOMAINS` | `sixthtone.com` | **必须**走无头浏览器渲染的域名，逗号分隔 |
| `RENDER_TIMEOUT_S` | `60` | 浏览器渲染超时（秒） |
| `JOB_WORKERS` | `2` | 后台抓取线程数 |
| `LLM_PROVIDER` | `deepseek` | 供应商名（仅用于展示） |
| `LLM_MODEL` | `deepseek-flash` | 模型名 |
| `LLM_BASE_URL` | `https://api.deepseek.com/v1` | OpenAI 兼容端点。**换供应商只改这三个值** |
| `LLM_API_KEY` | 空 | 密钥。**必填**，否则 AI 功能全 502 |
| `ECDICT_DB` | 空（= `<DATA_DIR>/stardict.db`） | 本地词典库路径，一般不用改 |
| `IPA_DICT_DIR` | 空（= `DATA_DIR`） | ipa-dict 两个 TSV 所在目录 |
| `DICT_AUTODOWNLOAD` | `true` | 启动时自检并**在后台补齐**缺失的词典数据（见 §2.3）。`false` 则只提示、不联网 |
| `DICT_API_BASE` | Wiktionary | **只用于录音回退**（有道拿不到时的备选源），音标不走这里 |
| `DICT_AUDIO_BASE` | `https://dict.youdao.com/dictvoice` | 发音来源。**非官方接口**，见下方说明 |
| `AUDIO_ACCENT` | `uk` | 默认口音（`uk` / `us`）。词卡上英美两个喇叭并列，这个值决定不带 `accent` 参数时取哪个 |
| `AUDIO_ENABLED` | `true` | 关掉就只用词典那张录音（`false` 时健康检查里 `audio.provider` 显示 `off`） |
| `AUDIO_MIN_INTERVAL` | `3.0` | 两次外向下载的**最小间隔**（秒）。调小会显著增加被风控的概率 |
| `AUDIO_JITTER` | `1.5` | 在间隔上再叠的随机抖动上限（秒）。**不要设 0** —— 固定节拍本身就是机器特征 |
| `AUDIO_TIMEOUT` | `20` | 单次下载超时（秒） |
| `AUDIO_MAX_ATTEMPTS` | `2` | 单次下载最多试几次（含首次）。失败按 2s→4s→8s 退避 |
| `AUDIO_BACKOFF_BASE` | `2.0` | 退避基数（秒） |
| `AUDIO_BREAKER_AFTER` | `5` | 连续失败几次进入熔断 |
| `AUDIO_BREAKER_COOLDOWN` | `600` | 熔断时长（秒）。期间一律走词典回退源 |
| `AUDIO_MIN_BYTES` | `1024` | 小于这个字节数不算音频（防拿到错误页） |
| `AUDIO_UA` | 一个常见桌面 Chrome UA | 下载发音时带的 User-Agent |

> `.env` 已在 `.gitignore` 里，不会进版本库。代码里没有任何硬编码密钥
> （`DESIGN.md §2.1`）。

**关于发音源**：有道 `dictvoice` 是非官方接口，覆盖率明显高于词典录音。
所以下载做了**刻意的慢**：全局串行 + 3 秒起步 + 随机抖动 + 退避重试 + 连续失败
熔断 10 分钟，而且**只下载你真正点过的词**（不预热、不扫生词本批量补）。
不建议调 `AUDIO_MIN_INTERVAL` / `AUDIO_JITTER`（`DESIGN.md §6.2`）。

**不填 key 会怎样**：服务照常启动，**划词查词完全不受影响**（本地词典，不需要 key），
发音（走有道，也不需要 key）照常可用；只有选段【解析】会返回 502。
用健康检查一眼确认：

```bash
curl http://127.0.0.1:8010/api/health
```

看到 `"api_key_set": false` 就是没配好。

## 4. 启动

**日常只需要起后端一个进程** —— 前端产物由后端同进程直发。只有在改前端代码时，
才需要额外开一个 Vite 终端（热更新）。

### 4.1 后端（端口 8010）

后端同时提供三样东西：界面（`/` 与 `/assets/*`）、接口（`/api/*`）、图片（`/media/*`）。

```bash
cd backend

uv run python -m app.main        # 推荐：不用 activate
```

等价写法：

```bash
.venv\Scripts\python -m app.main                        # 直接点 .venv 里的解释器
uvicorn app.main:app --host 127.0.0.1 --port 8010       # 已激活环境时
```

看到下面这行就算起来了：

```
Uvicorn running on http://127.0.0.1:8010  (Press CTRL+C to quit)
```

**验证**：浏览器打开 <http://127.0.0.1:8010/api/health>，应返回一段 JSON。
其中值得看的几个字段：

| 字段 | 含义 |
|---|---|
| `llm.api_key_set` | `true` 才算配好了 key（只影响选段【解析】） |
| `llm.prompt_version` | 当前 prompt 版本 |
| `dict.ecdict` | 本地词典库在不在、多大（**故意不报词条数** —— 340 万行的计数会把健康检查拖成秒级） |
| `dict.ipa` | 两个音标文件在不在；`entries` 为 `null` 表示还没查过词（内存表未加载） |
| `audio.provider` | 发音来源（`youdao` / `off`）、默认口音 `accent`，以及 `cached` / `missing` / `pending` 三个计数、按口音分的 `by_accent`、占用字节数、`breaker` 熔断状态 |
| `vocab` / `review.due_now` | 生词本总数 / 待复习张数，可用于自查 |
| `fetching` | 正在抓取的文章 id 列表 |
| `frontend.served` | 前端产物是否已由本进程托管。`false` 看启动日志（多半是还没 `npm run build`） |

后端还自带一份交互式 API 文档：<http://127.0.0.1:8010/docs>。

### 4.2 构建前端产物（首次，以及每次改完前端）

```bash
cd frontend
npm run build        # 产物落在 frontend/dist
```

没构建过也能起后端，只是打开 <http://127.0.0.1:8010> 会 404，`/api/*` 照常可用。
后端启动日志里会明确写出来：

```
INFO english | 前端产物已托管：C:\...\frontend\dist
# 或者
WARNING english | 未找到 C:\...\frontend\dist/index.html，跳过前端托管（先 npm run build）
```

**改了前端代码必须重新 `npm run build`** —— 后端发的是构建产物，不是源码。

### 4.3 改前端时 —— 再开 Vite（端口 5173，带热更新）

```bash
cd frontend
npm run dev
```

打开 <http://127.0.0.1:5173>。

Vite 把 `/api` 与 `/media` 反向代理到 `127.0.0.1:8010`，所以浏览器看到的是同源请求，
**不需要处理 CORS**，图片路径在开发与构建产物下完全一致（`frontend/vite.config.ts`）。

两个服务并存互不干扰：5173 用源码 + 热更新，8010 用构建产物。改完前端跑一次
`npm run build`，8010 那边刷新即是最新版。

### 4.4 只用 Vite 验产物（可选）

```bash
cd frontend
npm run preview      # 起 5173，已配好同样的代理
```

这是与 4.1 + 4.2 平行的另一条路（前端进程发产物、后端只做接口），选一条即可。
它旁边还有一条更省事的：`dist/` 是纯静态文件，直接把 `/api` 和 `/media`
反代到 8010 挂到 Nginx 上也行。

### 停止

几个终端就各自 `Ctrl+C`。后端会先跑完正在进行的抓取再退出（抓取在后台线程里）。

## 5. 使用流程

### 5.1 收藏一篇文章

1. 首页输入框粘贴文章 URL（支持 Sixth Tone、China Daily；其他站点多半也能抓，
   只是没有逐站调优）。
2. 点「抓取」。提示「已提交 #N，后台抓取中…」。
3. 列表里那条会显示状态：`排队中` → `抓取中` → `已完成`（失败则 `抓取失败`）。

**等多久**：

| 站点 | 耗时 | 原因 |
|---|---|---|
| China Daily | 约 3~5 秒 | 静态 HTML，直连 |
| Sixth Tone | 约 40 秒 | 无头浏览器渲染 + 等 JS 出图 |

抓取是**后台异步**的，提交后不用守着，可以继续看别的文章。
刷新首页看状态即可（前端每 3 秒轮询一次）。

**抓取失败的常见原因**：付费墙、反爬（403/Cloudflare）、URL 失效（404）。
失败的那条会记录原因，可以点重抓。

### 5.2 阅读

点文章标题或封面进阅读页。

顶部工具栏（全部即时生效，偏好存在浏览器本地）：

| 控件 | 作用 |
|---|---|
| 字号 `A-` / `A+` | 正文大小 |
| 行距 | 三档 |
| 栏宽 | 宽 / 窄 |
| 主题 | light / sepia / dark 三套配色，正文、高亮、侧栏联动 |
| 图片开关 | 一键隐藏原文图片（默写或专注阅读时用） |
| 返回 | 回文章列表 |

**阅读进度自动保存**：每 15 秒上报一次，关闭/切走页面时再补一次。下次打开这篇
文章会**自动回到上次读到的位置**。从未读过的文章返回空进度，不报错。

**右侧 AI 面板的宽度可以拖**：把鼠标移到面板**左边框**上（光标变成左右箭头、
那条边线亮成蓝色），按住往左拖就变宽、往右拖就变窄；范围 300–760px，窗口太窄时
上限会跟着收，免得正文被挤没。**双击那条边线复位成 380px**。宽度和其他阅读偏好
一样只存在浏览器本地，刷新、重开都还在，不写进数据库。

### 5.3 划词（单词）

**标题也能划**（和正文完全一样）：选中标题里的词会同样弹词卡、自动进生词本，
选中标题里的一段也一样能【解析】——标题是页面顶部那个 `<h1>`，
但它和正文块用的是同一套坐标，所以高亮、刷新后重建、从检索跳回来闪一下都成立。

选中一个单词（双击或拖选）：

- 浮层**立刻**出**英美两条音标** + 词性 + 中文释义（+ 英文释义）。全部来自本地
  词典库，**毫秒级、断网可用、不调模型**。
- 每条音标后面跟着**它自己的 🔊**（`🔊 英` / `🔊 美`）。**音频不预热：点哪个下哪个**，
  第一次点要等几秒（受 3 秒节流约束），下过之后就是本地文件、秒播。
- 英美音标相同时只显示一条（两个数据源对同一个词常常标得一字不差），但**两个喇叭
  都在** —— 音标相同不代表录音相同。
- 只有一边有音标就只显示一边（专名如 `Beijing`、`Thailand` 常常只有美音），
  但**缺的那一边喇叭照样给**：录音的有无和音标的有无是两件事。
- **音频下载到本地**（`backend/data/audio/`），播放在本机完成，不连外网。
- 变形词（`invading`）自己有词条，但音标/录音可能没有 —— 词卡会回退用**原形**
  （`invade`）的，并标注取自哪个原形。
- 这个词**已经自动进入生词本**，不需要再点任何按钮。
- **点正文里已经划过的单词（绿色高亮）会重新弹词卡** —— 当场重查本地词典，
  不依赖任何历史记录。反复点同一个词不会把「划过次数」刷上去。

> 与 M10 之前相比，词卡**少了**「在这句里的意思」「例句」「常见搭配」「易错提示」
> 这几栏 —— 那些只有模型能给。换来的是：不用联网、不用等、不烧 token。

两个和「划得准不准」有关的行为：

- **只划中词里几个字母也算数**：区间会**自动扩到整个单词**（想在 `Chang` 上划，
  手一抖只圈住了 `ha`，卡片给的仍是 `Chang`），卡片上会写一句「已按整词查」，
  落库和高亮也都是整个词。半截字母拿去查词典只会得到胡说八道，还会混进生词本。
  跨词、带空格的选区不受影响 —— 那是你真的想选一段。
- **底色分两类**：单词是绿色，短语 / 句子是黄色（见 §5.4）。长句里查过的词
  仍然顶着绿色，一眼就知道哪些词已经查过。

- 关掉词卡（点 ✕ / 点空白处 / Esc）时，那行字的**选中状态也会一起消失**。

**音标一定来自本地词典库**（红线 3）：主音标来自 ipa-dict（现代宽式 IPA，实测对
柯林斯/牛津核心词覆盖 88%~96%），它没收录时退回 ECDICT 自带的那条英式音标。
界面把 `ɹ` 显示成 `r`（学习词典惯例），并把 ECDICT 的老式写法（`ә`→`ə`、`:`→`ː`、
`'`→`ˈ`）在**显示层**整理成现代 IPA；数据库里存的仍是词典原文。

### 5.4 选段（句子 / 段落）

拖选一句或一段，浮层给一个按钮：

| 按钮 | 做什么 |
|---|---|
| **解析** | 一次给全：译文 + 主干 + 附加成分（挂靠关系）+ 短语 + 可复用的语法要点 |

解析结果是按「**主干 → 挂靠**」组织的，不是按语法类别分栏：

- **主干**：先给能读懂的句子骨架（主语 + 谓语 + 宾语 / 表语）；
- **附加成分**：每条都说清「挂在哪个成分上、起什么作用」；长难句还会单独点出
  难在哪（主干被什么隔开、哪一层嵌套最深）；
- **语法要点**：只收「换个句子也用得上」的结构，**自动进入本篇语法清单**；
  逐句的拆解（主干、附加成分）只留在解析结果里，不污染清单。

**为什么选段不自动解析**：拖选经常是误触或只是想看看有多长，自动解析纯属烧钱
（`DESIGN.md §7.2`）。点了才算数。

**而且点了才算「划过」**：划中一段句子不会留下任何东西 —— 正文里不出高亮、
清单里也不出条目。点过【解析】之后，那一句才会变成正文里的一处黄色标注，
并带着它的语法要点进清单。所以「划过头了」不需要清理：把浮层关掉就等于没划过。

点下去后右侧面板会**流式吐字** —— 文字一个字一个字长出来，不是干等转圈。
产出顺序就是「译文 → 主干 → 附加成分 → 语法要点」，只想看意思的等前几秒就够，
不必为「只想翻译」再单独留一个按钮。模型在「思考」阶段会显示提示和已用秒数。

跨块的选区会被拒绝（划词和选句都在句子内部，跨块只会得到半句话）。

选段的底色是**黄色**（与单词的绿色区分开），所以长句子里已经查过译的词仍然
一眼能认出来。点开某条痕迹看解析时，它外面会有一圈蓝框（表示「右侧面板正在看
这一条」）；**关掉右侧面板、点正文别处、或重新划一段，蓝框都会收掉**。

**右侧面板底部是「本篇解析记录」**：这一篇里每一次划词 / 解析都按时间倒序排在那里，
点一条就能回看当时的结果。划词是「选中即翻译」，手一抖难免多出记录 ——
**把鼠标移到某条记录上，右上角会出现 ✕，点它就删掉这条**。删的只是那一次查询：
原文高亮与生词本条目都不受影响；同一段文字再划一次会重新查、重新记一条。
检索页「AI 解析记录」那一组里的结果，也有同样的删除按钮。

### 5.5 生词本

导航「生词本」。**收录是自动的**，这里没有「加入生词本」按钮。

| 功能 | 说明 |
|---|---|
| 搜索 | 按词形或释义搜 |
| 按状态筛 | `全部` / `生词` / `在学` / `已掌握`（这是你自己标的，和复习进度是两回事） |
| 只看重点 | 「值得记」的词（`worth=1`）。判定由本地规则给出：命中中考/高考/四级标签 → 不算重点；命中六级/考研/托福/雅思/GRE，或是牛津三千、柯林斯四星以上 → 算重点。**只是筛选项，不是过滤掉** |
| 按文章筛 | 是「在这篇里划过」，不是「首次入册在这篇」 |
| 排序 | 按重要度 / 最新收录 / 划过最多 / 字母序 |
| 改释义、加批注 | 你自己的输入永远不会被词典覆盖 |
| 标为重点 / 移除 | 移除只删生词本这一行，**原文高亮和解析记录都不动** |
| 🔊 听发音 | 每行有**英美两个**喇叭，点哪个下哪个。来源见 §5.3 |
| 导出 | Anki CSV / Markdown |

> 同一个词的不同词形可能各占一行（`treasure` 与 `treasured`）。这是刻意的：
> `treasured` 作形容词在词典里本来就是独立条目，强行归并会把「现在分词作定语」
> 这类真正的独立词条揉进原形里。重复了就手动移除合并。

### 5.6 复习（间隔复习）

导航「复习」。系统按遗忘曲线把到期的词排好队。

**卡片正面**：词形 + 主音标 + 美英两个 🔊 喇叭 + 词性 —— 只有这些，释义不会提前泄露。
喇叭放在正面是有意的：正面本来就摆着音标，先听一遍不泄露答案，
而「想不起来怎么读」恰恰是要练的东西之一。

| 操作 | 效果 |
|---|---|
| `空格` 或「显示答案」按钮 | 翻面，看释义、语境义、文中例句。翻面前底部提示「按空格翻面」，翻面后变「按 1~4 评分」 |
| 「显示例句提示」按钮 | 显示文中例句，但目标词被 `﹏﹏` 挖掉。想不起来又不想看答案时用；再点一次收起 |
| `1` / `2` / `3` / `4` | 四档评分（也可以点按钮） |
| 「暂停复习这个词」 | 把这个词移出出题队列（仍在生词本里） |

**四档的含义与后果**（按钮上直接写着下次什么时候再见）：

| 键 | 档位 | 含义 | 后续 |
|---|---|---|---|
| `1` | 忘了 | 完全没想起来 | 回到学习阶段，间隔**折半**（不清零）；`lapses` +1 |
| `2` | 勉强 | 想起来了，但很费劲 | 间隔小幅增长 |
| `3` | 记得 | 正常答对 | 按难度因子正常增长 |
| `4` | 太简单 | 毫无压力 | 间隔大幅增长；新词可直接跳过学习步骤 |

**为什么「忘了」只折半不清零**：一次想不起来就从头来，用户会宁愿卡着也不点
「忘了」，复习数据反而全失真（`DESIGN.md §11`）。

**间隔上限 365 天，难度因子夹在 1.3 ~ 3.2** 之间，不会无限膨胀。

**队列规则**：

- 到期的旧词**不设上限** —— 欠的债要还。
- 新词**每天限量 20 个**（默认）—— 每天加一点，不会一上来堆几百张把人劝退。
- 排序：到期早的优先，新词垫后。

**暂停 / 恢复**：不想再看到某个词就暂停，它不再进出题队列，**但仍留在生词本
和检索里**。「暂时不想复习」和「这个词我不记了」是两件事，后者用生词本的移除。

**清空态**：队列清空后显示「本轮复习完成」或「现在没有到期的词」，并给出
「下次到期」时间。如果显示的是「—」，说明暂无可排期的卡。

### 5.7 检索

导航「检索」。一次输入，**三类结果一起返回**：

1. **原文正文** —— 命中段落，带上下文片段
2. **生词本** —— 词形或释义命中
3. **AI 记录** —— 历次解析内容命中（需求：AI 辅助过的内容可全文检索）

每条结果都能**跳回原文位置并闪两下**定位到具体那句。

> 检索基于 SQLite FTS5。英文按 porter 词干索引，所以搜前缀可能撞词干：
> `sitt` 匹配不到索引里的 `sit`，搜完整的 `sitting` 或 `sit` 更稳。
> 中文另走 `LIKE` 兜底（FTS5 的 unicode61 不切分汉字）。

### 5.8 单篇汇总与导出

文章页 → 汇总。两块内容：

- **生词表**：本篇划过线的所有词（音标、词性、释义、文中例句）
- **语法清单**：本篇的语法点，可按类别分组

> 没有「划了线但还没解析」这一栏：划一段句子不落痕（见 §5.4），点过【解析】
> 才有痕迹与解析记录。清单里的每一行都对应一次真实发生过的解析。

三个导出按钮：

| 格式 | 用途 |
|---|---|
| **导出清单 MD** | 生词 + 语法的汇总清单，直接阅读、二次加工 |
| **导出 Anki CSV** | 导入 Anki。首行是 `#separator:Comma`，**刻意不写 BOM**（多一个 BOM 会被 Anki 当成普通笔记） |
| **导出原文 MD** | 只要正文；图片指向 `/media`，服务在跑就能预览 |

生词本页面也有独立的整体导出，可按文章或状态限定范围。

## 6. 数据在哪 / 怎么备份

一切都在 `backend/data/`（路径由 `DATA_DIR` 决定）：

```
backend/data/
├── english.db          # SQLite：文章、正文块、痕迹、生词本、语法点、AI 流水、复习进度
├── stardict.db         # 本地词典库（ECDICT，约 811 MB）：释义/词性/标签/词频
├── ipa_en_us.txt       # 美音音标（ipa-dict）
├── ipa_en_uk.txt       # 英音音标（ipa-dict）
├── raw/                # 抓到的原始 HTML（重抓前先存一份，防站点改版）
├── assets/{id}/        # 本地化后的文章图片
├── audio/              # 本地化的单词发音，按内容哈希命名（`<16位>.mp3`）
├── exports/            # 导出产物（脚本导出落这里；页面导出走浏览器下载）
├── m0/ m2_shots/ … m5_shots/   # 各里程碑验收脚本的产物，与服务端数据分开
```

> `english.db` 是**可再生的**：删掉它重启服务就会按 `schema.sql` 重建
> （学习记录当然也没了）。上面三个词典文件是**外部数据**，删了也没关系 ——
> 服务启动时会自检并自动重下（见 §2.3）；不想联网就 `python scripts/fetch_dicts.py`。

**`audio/` 的命名为什么是哈希**：`sha256(文件字节)[:16]` + 真实扩展名（由魔数嗅探，
不信 URL 后缀）。好处是换源重下、或两个词共用同一份录音，都不会产生重复文件；
代价是文件名看不出是哪个词 —— 要知道某个词对应哪个文件，查
`english.db` 里 `audio_cache` 表的 `path` 列（`DESIGN.md §6.1.1`）。

**备份**：直接拷 `backend/data/` 整个目录即可。
**迁移**：把 `data/` 拷到新机器，启动服务即自动建表。

> 这个目录**不在版本库**（`.gitignore` 已排除）。文章正文和图片有版权，仅限
> 本地个人学习使用，不要公开分发。

**数据库备份注意**：SQLite 开了 WAL，热备份要连 `english.db-wal`、`english.db-shm`
一起拷，或者先停服务再拷。

| `smoke_ui_m4.py` | 浏览器：生词本、清单、检索、导出 | 59+/59+ |

**跑浏览器验收前**：后端（8010）必须在跑。前端有两个选择 —— 默认打 Vite（5173，
需要 `npm run dev` 在跑），或者用 `FRONT_URL` 指到 8010 直接验构建产物（此时不需要
Vite，但要先 `npm run build`）。都用真实浏览器
（Playwright Chromium，`python -m playwright install chromium` 已包含）。

```bash
# 后端验收（不需要前端）
python scripts/smoke_m5.py

# 浏览器验收 —— 打 Vite 开发服（需 5173 在跑）
python scripts/smoke_ui_m5.py

# 浏览器验收 —— 打后端直发的构建产物（需先 npm run build，不需要 5173）
FRONT_URL=http://127.0.0.1:8010 python scripts/smoke_ui_m5.py
```

> `smoke_ui_m5.py` 会先把真实复习卡**暂停并快照**（`quarantine`），造一次性卡
> 做验收，结束时还原 —— 跑验收不会打乱你的复习进度。
>
> `smoke_m10.py` 会造 `m10probe*` 探针词与临时文章来验证入册与发音，收尾时
> 只清这个前缀的行（连同孤儿音频文件），正常词汇与已下载的音频不受影响。
> 它的发音组会**真的点一次喇叭**（走同一把节流闸门），所以单次运行大约十几次外部请求。
>
> `smoke_ui.py` 的「刷新后回到原位置」一项偶发抖动（偏差阈值 12%）：图片是懒加载
> 的，加载进度会影响页面总高，进而影响百分比。重跑一次即过，不是回归。
>
> `smoke_m9.py` 会**掐断**词典与模型请求（测的是「标题能不能像正文一样划」，
> 不需要真调模型），所以跑它不会往生词本里塞测试词，也不烧 token。它造的两条痕迹
> 收尾时自己删掉，并断言「跑之前几条、跑完还是几条」。夹具（短语/词/片段）从标题
> 里现派生，换一篇文章照跑。

## 8. 常见问题排查

### 启动类

| 现象 | 原因与处理 |
|---|---|
| `error while attempting to bind on address ... 10048` | 8010 端口被占。多是上一次的后端没退干净：`netstat -ano \| findstr :8010` 找 PID，再 `taskkill /PID <pid> /F`；或换端口但要同步改 `frontend/vite.config.ts` 里的 `BACKEND` |
| 前端报端口 5173 被占 | `strictPort: true`，不会自动换端口。让占用的进程退出，或改 `vite.config.ts` |
| `ModuleNotFoundError: app` | 不在 `backend/` 目录下跑，或虚拟环境没激活 |
| `ModuleNotFoundError: fastapi`（用 `uv run` 时） | `backend/.venv` 还没建，uv 退回了自己管的空解释器。先按 §2.1 跑 `uv venv` + `uv pip install -r requirements.txt`。uv 只在**当前目录及其父目录**找 `.venv`，所以务必先 `cd backend` |
| 浏览器打开 5173 白屏、控制台全是 404 | 后端没起。前端只做代理，后端不在就没有 `/api` |
| 打开 8010 根路径 404，但 `/api/health` 正常 | 前端产物没构建。`cd frontend && npm run build`，再重启后端（启动日志会写「跳过前端托管」） |
| 8010 打开还是旧界面 | 后端发的是构建产物，改完前端要重新 `npm run build`。`index.html` 是 `no-cache`，刷新即可；`/assets/*` 带内容哈希，文件名变了自然会重新拉 |
| 8010 上直接刷新 `/a/3?block=12` 打不开 | 只应该有 404 一种情况：`SERVE_FRONTEND=false`。正常配置下这类深链会回退到 `index.html` 由前端路由接管 |

### 抓取类

| 现象 | 原因与处理 |
|---|---|
| 状态一直 `抓取中` | Sixth Tone 要 40 秒左右。超 2 分钟没动静就看后端终端的日志 |
| 状态 `failed`，原因 403 / Cloudflare | 反爬。把该域名加进 `RENDER_DOMAINS`（走无头浏览器），或等一会儿重试 |
| 状态 `failed`，原因 404 | URL 失效，或该 URL 需要登录 / 有付费墙 |
| 抓到了但正文很短 | 站点改版，选择器没命中。看 `data/raw/` 里的原始 HTML 确认 |
| 图片显示成裂图 | 图床防盗链（实测 `img2.chinadaily.com.cn`）。重抓一次；下载时会带 `Referer` |
| 想强制重新渲染 | 文章页点「重抓」。**重抓不影响已有学习痕迹**（`DESIGN.md §4.3`） |

### AI 类

| 现象 | 原因与处理 |
|---|---|
| 点按钮返回 502 | 依次查：`.env` 里 `LLM_API_KEY` 填了吗（`/api/health` 的 `api_key_set`）、key 有余额吗、能不能访问 `api.deepseek.com` |
| 报 `finish_reason=length` | 模型输出被 `max_tokens` 截断。代码会自动把预算翻倍重试一次（`DESIGN.md §6.4`） |
| 结果秒回但和上次不一样 | 正常：命中缓存返回的是**上次那份**。改了 prompt 必须升 `PROMPT_VERSION`，否则新逻辑会被旧缓存盖掉 |
| 流式输出中途断掉 | 前端会报「连接中断」（没收到终帧就是结果不完整）。**已生成的部分仍在后台落库**，看流水列表能找回来 |
| 音标是空的 | 该词在两个本地词典里都没有记录（生造词、部分专名）。**不会用模型编一个**，宁缺勿假 |
| 音标和词形对不上 | 划到变形词（`invading`）而它自己没有音标时，取的是**原形**（`invade`）的读音，界面会标注「音标取自原形」。词形自己有音标时就是用词形的（人在文章里读的是它） |
| 同一个词，生词本和词卡的音标不一样 | 不该出现。展示口径已统一为**美音优先**（`dictionary.primary_phonetic`），若仍不一致请报 bug |
| 划词提示「本地词典库没有安装」 | `backend/data/` 下的 `stardict.db` 不在（多半是首次启动、数据还在下）。看 `/api/health` 的 `dict.bootstrap`：`downloading` 就是在下（词卡会显示百分比），`error` 是下载失败（重启服务会重试，或跑 `python scripts/fetch_dicts.py`），`off` 说明 `DICT_AUTODOWNLOAD=false`（§2.3） |
| 划词提示「词典未收录这个词」 | 词典库在，但两个库都没这个词条（数字、拼写错误、极生僻）。查词本身没问题 |

### 发音类

| 现象 | 原因与处理 |
|---|---|
| 某个口音没有 🔊 按钮 | 后端**明确知道**那个口音没录音（`status = missing`）。这个口音的录音两个源都没有，**不是所有词都有英美两份录音**。另一个口音的喇叭不受影响 |
| 喇叭标着 `🔊 英` 但听起来像美音 | 有道没有这个词，回退到词典录音时拿到了别的口音。后端会照实记录（`audio_cache.got_accent`），界面按钮按你点的那一栏标注；听感异常时看后端日志的 `发音已本地化 <词>[uk]（wiktionary/us…）` |
| 第一次点 🔊 要等几秒 | 正常：**音频不预热，点了才下**（受 3 秒起步的节流约束）。下过一次之后就是本地文件，秒播 |
| 点了 🔊 显示「音频不可用」 | 音频确实没下下来（网络问题，或回退源给的是 Safari 放不了的 `.ogg`）。看后端日志；必要时把 `AUDIO_ENABLED=false` 只用词典源，或换个网络 |
| 一段时间内所有词都拿不到有道音频 | **熔断被触发了**（连续失败 5 次，静默 10 分钟，可能是网络抖动也真可能是被风控）。看 `/api/health` 的 `audio.breaker`；期间会自动走词典回退源，不用手动干预 |
| 想清掉已下载的发音 | 直接删 `backend/data/audio/` 下的文件即可（不用停服务）。`audio_cache` 里那些行会**自动失效**：台账说 `ok` 但文件不在时，接口把它降级成 `pending`，下次点喇叭重新下（删了文件不删行也不会 404） |
| 想换个发音源 | 改 `DICT_AUDIO_BASE`。但换源后已缓存的行不会自动作废 —— 需要 `?refresh=1` 逐个重取，或清掉 `audio_cache` 的对应行（见 `DESIGN.md §11`） |
| 想让某个词重下一遍 | `GET /api/dict/{word}/audio?accent=uk&refresh=1`，或在浏览器里打开这个地址 |

### 复习类

| 现象 | 原因与处理 |
|---|---|
| 复习页说「今天没有要复习的」 | 正常：还没到期的卡。去生词本确认词在不在 |
| 生词本有词，复习队列却是空的 | 这些词都被**暂停**了。在生词本里恢复 |
| 新词一直不出现 | 新词每天限量 20 个。先清完到期的旧词 |
| 一个词反复出现 | 反复点「忘了」会让它退回学习阶段（分钟级间隔），几分钟内确实会再来一次，属于正常 |
| 想彻底不再复习某个词 | 生词本里「移除」，不要用暂停 |

### 检索类

| 现象 | 原因与处理 |
|---|---|
| 搜不到明明存在的正文 | FTS5 按 porter 词干索引，搜完整的词形或词干，别用截断前缀 |
| 搜中文没结果 | 中文走 `LIKE` 兜底，能搜但只做子串匹配，不分词 |
| 搜 `a OR b` 返回 500 | 旧版本的坑，已修（查询串里的运算符会被转义成普通词）。遇到就重启后端 |

### 数据类

| 现象 | 原因与处理 |
|---|---|
| 想清空重来 | **危险操作**。先关服务，备份 `data/`，再删 `english.db`（会连带丢失所有学习记录） |
| 换了机器打不开 | 库里的图片路径是相对 `DATA_DIR` 的，整个 `data/` 一起搬 |
| Anki 导入变成一堆普通笔记 | 导出文件的**第一个字节**被加过 BOM。用页面的导出按钮，不要手动改文件 |

## 9. 成本与隐私

**成本**：AI 调用全部走 `input_hash` 缓存，同一个请求内容第二次问是 0 token。
实测一轮完整学习（73 次调用、61 次真实调用、12 次命中缓存）累计消耗约 7.4 万
token，按 DeepSeek 的价格属于几毛钱量级。只有点【解析】才产生调用 ——
**阅读、划词查释义、听发音全都不烧钱**（前两者是本地文件，发音只走有道）。

自查看消耗：

```bash
curl http://127.0.0.1:8010/api/ai/stats
```

返回调用次数、缓存命中数、token 总量。

**隐私**：

- 所有数据（正文、图片、发音音频、痕迹、生词本、复习进度）**只存在本机**
  `backend/data/`。
- 对外发出的请求只有两类：把选中的文本发给 DeepSeek 做解析；把单词发给有道取发音。
  **划词查释义完全不出网** —— 音标与释义读的是本地词典库（`stardict.db` /
  `ipa_en_*.txt`），这也意味着划词时不会把你正在读的词暴露给任何第三方。
  （只有「有道也没有该词录音」时，才会去 Wiktionary 抓一次录音候选。）
- 发音音频**下载到本地后就不再联外网**，浏览器播放读的是本机文件。这一条既是
  速度，也是隐私 —— 你查过哪些词不必每次都向外暴露。
- 有道那条虽然是非官方接口，但发出去的只有单词本身（GET 查询串），不带任何
  本地路径、账号或文章内容；下载频率也被刻意压到很低（见 §3 配置项）。
- `.env` 里的 key 不会被任何接口回显（健康检查只返回「配没配」）。
- **版权**：抓下来的正文和图片仅限本地个人学习使用，不要公开分发，保留原文 URL
  和来源标注。本地化的发音音频同样不要二次分发。
